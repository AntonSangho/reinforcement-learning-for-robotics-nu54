## 2. 잘된 점

- **로그로 증상을 갈랐다.** "버튼이 꺼졌다"는 관찰을 그대로 받지 않고 부팅 횟수를 봐서 재부팅으로 바꿔 읽었다. 리셋 원인·부팅 횟수 두 줄을 넣은 것이 이후 모든 판단(빵판 아님 → J2)의 근거가 됐다.
- **좌우를 나눠 본 숫자가 배선 문제를 짚었다.** "한쪽 바퀴만 움직이는 듯"을 좌우 \|duty\|와 \|바퀴 속도\|로 나누자 "duty 2배, 속도 6배 작음"이 나왔고, 바퀴 든 채 단독 구동 → "바퀴는 도는데 틱 0"으로 엔코더까지 좁혔다.
- **모터가 도는 동작 전에는 각도와 바퀴 들기를 확인했다.** 사용자가 세운 채 버튼을 누르겠다고 했을 때 바퀴를 띄우라고 먼저 알렸다.
- **관찰을 먼저 물었다.** D1-3의 "LED가 꺼짐", D1-4의 "전보다 안정적"은 숫자를 보기 전에 받았다.

| 재부팅 원인을 빵판으로 먼저 의심 | 빵판 접촉 문제가 이전에도 있었음 | 전원 경로(배터리 → J2 → DC-DC → VEXT)의 모든 접점을 같이 본다. 스위치·커넥터도 |

| 손 회전 엔코더가 −로 나옴 | 바퀴를 뒤로 돌림 | 방향은 모터 + duty로 확인 (눈 + 틱) |

## 4. 알게 된 것 (해석은 사용자 몫, 질문으로 남김)

- 관측 하나(왼쪽 바퀴 속도)가 틀리자 정책은 그쪽 duty를 키웠다. 정책은 "명령하면 바퀴가 이만큼 돈다"를 시뮬레이션에서 배웠다 → `rl-notes` Q6
- 좌우가 맞은 뒤에도 손을 떼면 뒤로 가속하다 duty 상한(60 %, 약 10.8 rad/s)에 닿고 넘어졌다. 세션 15 C·C2도 손을 떼면 뒤로 −6 rad/s였다 → `rl-notes` Q7
- D1-5(손 댐)에서도 처음 6초는 평균 duty −11\~−13 %, 바퀴 평균 −1.7 rad/s(뒤로)였다
- 파란 LED를 저항 없이 GPIO에 달았다. 순방향 전압이 3.3 V에 가까워 지금은 문제없지만 정격은 넘을 수 있다

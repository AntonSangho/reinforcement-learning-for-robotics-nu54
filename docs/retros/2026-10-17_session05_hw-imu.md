# 세션 5 회고 — IMU 모듈 (2026-10-17)

## 1. 한 일

| 결과물 | 내용 |
|---|---|
| `imu` 모듈 | MPU-6050 드라이버와 CLI (`info/read/watch/cal/clear`), 빌드·J-Link 플래시 |
| 정지 시험 | Z ≈ +1 g, 보정 후 자이로 ±0.1 dps |
| 기울이기 시험 | pitch 축 = 가속도 X + 자이로 Y, `pitch = +atan2(ax, az)`, `pitch_rate = −gy` |
| 문서 | `hardware.md` §4·§5-6, Issue #11 체크리스트·코멘트, #9 링크 |

## 2. 잘된 점

- **센서 축을 기판 그림 대신 기울이기로 측정했다.** 가속도 각도와 자이로 적분 각도가 일치해서 축과 스케일이 동시에 검증됐다.
- **시뮬레이션의 pitch 정의(`−atan2(accel_x, accel_z)`, `gyro[1]`)를 코드에서 읽어 와서** 실측 부호를 그 규약에 맞췄다.

## 3. 시간이 걸린 점과 원인

| 문제 | 원인 | 다음에는 |
|---|---|---|
| baram-term을 사용자에게 띄우라고 안내했다가 정정받음 | 보드 조작은 Claude가 한다는 원칙을 baram-term 실행에는 적용하지 않았다 | 포트를 찾아 직접 `baram-term`을 백그라운드로 띄우고, 외부 제어가 꺼져 있을 때만 사용자에게 요청한다 (메모리에 반영) |
| 첫 기울이기 기록이 쓸모없었음 | `baram-ctl read`가 최근 일부만 돌려줌, 사람 동작과 기록 시작 시각이 안 맞음 | 실시간 기록은 `baram-ctl send ... --until <안 맞는 정규식> --timeout N`으로 한 번에 받는다 |
| 보정 바이어스가 매번 다름 | 자세를 옮긴 직후 또는 칩이 안정되기 전에 보정 | 고정 후 몇 초 기다렸다가 두 번 보정해 비교 |

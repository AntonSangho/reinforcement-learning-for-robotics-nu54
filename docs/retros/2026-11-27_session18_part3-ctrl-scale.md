## 2. 잘된 점

- **사용자의 우선순위를 따랐다.** "생각이 진행에 도움이 되나, 배움용인가"라는 질문에 둘 다라고 솔직하게 답했고, 사용자가 "동작 파악이 우선"이라 하자 바로 RUN으로 갔다. RUN 결과가 다시 질문(Q7)으로 이어졌을 때도 사용자가 넘기자 측정으로 바꿔 진행했다.
- **해석 대신 측정으로 좁혔다.** "vel 부호가 sim과 다를까"는 추측 대신 시뮬레이션 몇 초로 확인했고(같음), 그 과정에서 "같은 행동인데 시뮬레이션은 바퀴가 느려지고 실물은 빨라진다"는 차이가 나왔다. 바퀴 든 채 duty 30 % 시험을 시뮬레이션에서도 똑같이 해 숫자로 비교했다.
- **바꾼 것을 하나로 유지했다.** O5 → S1은 배율만 바꿨고, S1이 애매하자 S2(40 %)로 추세를 보고 S3에서 S1을 반복했다. 반복이 없었다면 "50 %는 3초"로 끝났을 것이다.
- **보드 도구를 직접 세웠다.** baram-term이 꺼져 있을 때 사용자에게 명령을 넘기지 않고 VCOM1(`-if03`)로 직접 띄웠다.

## 4. 알게 된 것 (해석은 사용자 몫, 질문으로 남김)

- offset을 9.5 / 6 / −6으로 바꿔도 모두 **앞으로** 돌진했다. offset만으로는 설명되지 않는다
- 정책은 바퀴 속도 +5 rad/s에 행동 +0.62를 낸다 (pitch +0.05 rad에는 +0.17). O5에서 정책 pitch가 뒤(−0.03)인데도 바퀴는 앞으로 가속했다
- 시뮬레이션은 같은 상황(+5·+8 rad/s로 굴러가며 시작)에서 바퀴가 느려지며 선다. 바퀴 든 채 같은 duty에서 실물 모터가 약 20 % 빠르다
- 배율 60 → 50 → 40: 서 있던 시간 1초 → 3초(S1)·115초(S3) → 0초. 같은 조건에서 3초와 115초로 갈렸다 → 여유가 작은 상태일 수 있다
- S3에서도 좌우 duty 부호가 자주 엇갈리는 작은 떨림, 60초에 0.25 m 앞으로 흐름, `imu fail 3`
- 시뮬레이션 모터 비교는 바퀴를 든 채(무부하)다. 바닥에서 몸통을 싣고 달릴 때도 같은 비율인지는 모른다

## 2. 잘된 점

- **가설을 사용자가 세웠다.** "왜 떨리는지 감이 없다"에서 기록 한 줄 → 틱 1개 = 0.84 rad/s 계산 → 0.2 rad/s 바퀴의 틱 순서 → 정책 출력으로 단계를 쪼개자 사용자가 "출력이 튀고 바퀴가 돌았다 멈췄다 해서 떨린다"를 직접 말했다.
- **예측 → 시험 → 결과를 지켰다.** A·B·C 모두 예측을 먼저 적고 돌렸다. 잡은 채로는 duty가 데드존 아래라서 "떨림 없음"이 균형의 증거가 아니라는 점을 결과 칸에 같이 적었다.
- **관찰은 자유 서술 먼저.** 매 RUN 뒤 숫자 요약을 보여 주되 해석 전에 "어떻게 보였나요?"를 물었다. 시험 C의 정지 구간(물체에 기댐)은 숫자만으로는 알 수 없었다.
- **모터가 도는 명령 전에는 각도를 확인했다.** 기울어진 채 시작 요청이 4번 있었는데(55°, 54°, −11°, −17°) 모두 모터 없이 건너뛰었다. 마지막에는 ±5°에서 0.6초 머물면 자동 시작으로 바꿨다.

## 4. 알게 된 것 (해석은 사용자 몫, 질문으로 남김)

- 원본 펌웨어의 바퀴 속도 계산(5 ms 틱 차이)을 그대로 쓰면 우리 엔코더에서는 0.84 rad/s 계단이 된다. 원본 Bala2는 420틱/회전이라 계단이 3.6배 더 크다 — 원본은 왜 됐을까? (영상의 펌웨어 보정 4개, 회고 13 §4)
- 손을 떼면 다시 떨리고 좌우 duty가 자주 반대 부호였다. 잡았을 때(A)와 무엇이 다른가
- 손을 뗄 때마다 뒤로 −6 rad/s까지 달렸다. pitch ≈ 0인데 바퀴가 뒤로 돌수록 정책이 더 뒤로 명령했다 (시험 C 1.2\~1.9 s)
- 루프 주기는 실측 4.1\~5.1 ms. 처음 한 주기만 짧고(ms 단위 sleep) 이후는 5 ms ± 50 µs

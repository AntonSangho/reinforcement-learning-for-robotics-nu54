## 3. 시간이 걸린 점과 원인

| 문제 | 원인 | 다음에는 |
|---|---|---|
| 첫 학습이 `PermissionError` | 세션 13에서 Claude가 `docker exec`(기본 root)로 스모크 학습 → `runs/`가 root 소유 | `docker exec -u abc` (CLAUDE.md 반영). 학습 전에 `find workspace -user root` |
| "학습 timestep 2 ms"라고 잘못 안내 | 노트북 주석(Bala2 기준 `2048 * 0.002s`)을 믿고 `nu54.xml`을 확인하지 않음 | timestep은 MJCF의 `<option timestep>`부터 확인 |
| `[*]` 대기열을 취소할 수 없음 | Shift+Enter를 여러 번 눌러 셀이 줄을 섬. Interrupt는 학습까지 멈춤 | 긴 학습 셀은 한 번만 실행하고, 끝 알림은 Claude가 파일을 백그라운드로 지켜봄 |
| 관찰 답을 한 번 정정 | 선택지 질문에서 단계·모양을 먼저 고르게 함 | 관찰은 "어떻게 움직였나요?"로 자유 서술을 먼저 받고 숫자로 확인 |
| 표 안의 `\|ctrl\|`이 열을 나눔 | GFM은 코드 안의 `\|`도 열 구분자로 봄 | 표 안에서는 `\|`로 이스케이프 |

## 4. Part 3로 넘어가기 전에 알게 된 것

- 펌웨어는 `actor.onnx`(평균 행동)를 쓴다. 2단계 정책의 평균 행동은 `\|ctrl\|` 중앙값 0.010으로 시뮬레이션 데드존(0.12)보다 훨씬 작다
- 모델의 데드존 0.12(`frictionloss` 0.02 N·m)는 6 V 실측 duty 15 %를 12 V로 환산한 값이다 (ctrl 0.12 = duty 약 7 %). 실물 데드존은 12\~18 %로 불규칙했고 배터리 전압에서는 직접 재지 않았다 → 실물이 모델보다 클지 작을지 모른다
- 시뮬레이션에서 2단계 평균 행동이 제자리에 서 있었던 것이 실물에서도 그대로일지는 확인해야 한다 (예측 질문으로 남김)
- 그래서 Part 3 첫 시험은 1단계와 2단계 `best_model`을 둘 다 `actor.h`로 만들어 두고 CLI로 고를 수 있게 하면 비교가 쉽다. 두 모델은 `results/phase1·phase2/best_model.cleanrl_model`
- 새 PyTorch exporter는 가중치를 `actor.onnx.data`에 따로 저장한다. `onnx_actor_to_c.py`는 `onnx.load()`(기본값으로 같은 폴더의 외부 데이터를 읽음)를 쓰므로 두 파일을 같은 폴더에 두면 된다
